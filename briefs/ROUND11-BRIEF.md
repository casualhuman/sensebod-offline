# Sensebod round 11 — Admin (content manager)

## Purpose
An admin area, served by the Raspberry Pi in the bag, where an EasySTEM facilitator or teacher uploads and organises the content that populates every learner screen already designed (portals → audiences/classes → series → lessons). No internet: the admin connects to the bag's Wi-Fi and opens e.g. `http://materials.sensebod.com/admin` on a laptop (primary) or tablet. Users are semi-technical (teachers, facilitators): denser than learner screens is fine, but keep plain language, clear steps, big enough targets (≥44px), visible labels, and the V3 look.

## Look
Reuse the V3 light design system: `project/V3-Components.dc.html` (tokens, buttons, cards, Lesson types section with the Watch / Listen / Try it / Check tags and the "You take part" modifier), `project/Main.dc.html`, Style B lesson cards in `project/CPB-Child.dc.html` (so admins see the same cards learners will see). Poppins, blue #085CAA primary, ink #15233B, slate #4A5568, page #F4F7FB, white cards, green #1F7A3A for Agriculture and success, red #C41E2A only for errors/destructive, gold only on Listen. Contrast ≥ AA. Bold D-style icons with labels. Layout: a left sidebar nav (Sensebod logo `/_blob/85b192cd7d9b6351c5c7df6e9a0a36d1`, "Admin" label; items: Library, Add lesson, Series and order, Learners and progress, Storage and backup, Settings; the device status "Running on this bag · No internet needed") + main content. These are web-app PAGES: give each board a fluid root (no fixed px width; max-width container ~1360px, side menu + content in a `flex-wrap: wrap` row so it stacks at narrow widths), designed and sized for 1440 wide; set `$preview` width 1440 and the content height, and report it.

## Content model (must match the learner screens)
Portal (Primary school, Junior secondary, Child protection, Agriculture, Climate) → for Primary/JSS a class (Class 1–6 / JSS 1–3) and subject; for Child protection an audience (Child · Parent or carer · Community elder); for Agriculture/Climate a topic → Series → Lessons in order. Each lesson: type tag (Watch | Listen | Try it | Check), "You take part" (interactive) on/off, title, short "What you will learn", language (English / Krio / other), files (media; captions .vtt/.srt for Watch; Read-along text for Listen; animation package .zip/HTML for Try it; questions for Check and interactive video), cover picture, length (auto-detected after upload), Needs sound, status (Draft / Published), last edited, size on disk. Use real sample content: Agriculture livestock videos really on the Pi (e.g. "Quail housing", "Breeding rabbits", "Hand milking of dairy cows" — 64 livestock videos, 3.3 GB); Child protection series (Child: L1 Watch "My body belongs to me", L2 Listen "Safe and unsafe touch", L3 Try it "Who can I tell?", L4 Watch + You take part "It is not my fault", Check). Don't invent other statistics; unknowns as [placeholders]. Storage: show "[used] of [total] GB used" placeholders except the known 3.3 GB of livestock videos.

## Format
`.dc.html` rules in ROUND2-BRIEF.md (skeleton, rules that bite). Real `<input>`, `<label>`, `<select>`, `<button>`, `<a href>`. Each board's own `<title>`. Inline stroke SVG icons. Under 220 KB per board. You may render boards in a scratch browser to check layout; do not publish. Write only your files into `project/`.
