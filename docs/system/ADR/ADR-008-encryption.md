# ADR-008 — Backups encrypted with `age` to EasySTEM public keys; learner data as AES-256 zip with a one-time password

**Status:** Proposed · 12 Nov 2026 · revised 13 Nov 2026 (revision 1)

**Decision.** (1) Every backup file (`.sbk`) is a tar stream encrypted with `age` to the X25519 public keys in `/etc/sensebod-offline/backup-recipients.txt` (at least two EasySTEM keys held separately). The bag cannot decrypt its own backups. (2) "Download learner data" is a zip with WinZip AES-256 (AE-2) encryption, written by any streaming AE-2-capable zip writer (SYSTEM-ARCHITECTURE §4.1 R-8), password generated by the bag (4 words + 2 digits), shown once, held only in a tmpfs file (`/run/sensebod-offline/export-secrets/`) until the job ends — never in SQLite or the idempotency record. With names included, the file goes to a USB stick by default. (3) Diagnostics are unencrypted and contain no personal data. (4) Media on USB full backups is not encrypted (configurable).

**Context.** Files leave the bag over a plain-HTTP Wi-Fi whose password every learner knows, onto phones, laptops and sticks that can be lost; the data concerns children; facilitators are not technical; partners must open learner-data files with ordinary tools.

**Alternatives.** Password-protected backups (a forgotten password loses the backup; a weak one protects nothing); no encryption (unacceptable for children's data); GPG (heavier, error-prone UX); ZipCrypto (broken); public-key encryption for partner files (partners lack tools); encrypting media (cost without benefit; content is public on the Wi-Fi).

**Rationale.** Public-key encryption lets an unattended bag make backups no thief can read, with no secret on the bag. `age` is small, audited, in Debian, streams, and authenticates chunks (truncation detected). AES zips open in 7-Zip/Keka/ZArchiver.

**Trade-offs.** Restore always needs EasySTEM (technician). Windows/macOS built-in unzip cannot open AES zips — recipients need 7-Zip (owner question O-2). The AE-2 writer is a dependency to prove — **PoC P-2 on the Pi**.

**Consequences.** Key management at EasySTEM (O-11): who holds the private keys, rotation by release, at least two keys.

**Revisit when.** Partners need unencrypted files (owner), or a central server replaces USB (phase 2 transport encryption still keeps age at rest).

**Revision 1 (13 Nov 2026).** V-004: the v0.1 "wipe from the job payload" left the password in the idempotency record, in snapshots and (with an open reader) in the WAL (measured by the verifier); it now never touches the database, and a job never writes an unencrypted zip when encryption was requested. V-005: the zip password protects the file **at rest only** — it is shown in the same plain-HTTP channel as the download link, so it does not stop a Wi-Fi sniffer; the threat table says so, and names-included exports go to USB by default (override with warning, audited). Sealing the password to a key generated in the page (TweetNaCl) was considered and **not adopted**: the same sniffer can take the admin session (T-2), the library is unmeasured on Chrome 58, and USB already removes the file from the Wi-Fi. Revisit with HTTPS.

**Revision 2 (13 Nov 2026).** V-021: password files orphaned by a failed API transaction are deleted by the API's error path or, at the latest, by the next maintenance run (≤ 15 min). V-004 remainder: the api, worker and maint units list `/run/sensebod-offline/export-secrets` in `ReadWritePaths` under `ProtectSystem=strict` (SYSTEM-ARCHITECTURE §10.2, test EX-9).

**OWNER-1 (13 Nov 2026).** The earlier Python library choice is removed; for Node.js, examples are an AES-zip plug-in for a zip streaming library, or the Debian `7zip` CLI fed the password through a pipe (never on the command line). Examples only.

**Revision 3 (13 Nov 2026).** V-027: R-8 now accepts AE-1 or AE-2, written streaming or from `.tmp/` files, and the password must never be on argv or in the environment. Proven cheaply on the Mac: a writer and reader using only `node:crypto` and `node:zlib` interoperate with libarchive both ways, refuse a wrong password and detect tampering (`poc/poc_ae2.out`). libarchive itself wrote AE-1 for the small test CSV (and AE-2 for an 18-byte file in a separate scratch test). P-2 remains the gate on the Pi with 7-Zip and ZArchiver.
