**Summary.** I accepted all 18 findings and changed the documents for each one. I rejected none. For three of them I chose not to do the optional, stronger part of the suggested fix, and I give my reasons in §2: V-005 (sealing the password with TweetNaCl), V-010 (a third backend process) and V-014(d) (Child protection lesson addresses can still stay in the browser history). One point of V-018 needs the owner, because it concerns public DNS. No document in `reviews/` was changed, and no file outside `docs/system/` was touched.

**New or extended evidence.** All runs were on the development Mac, not on a Pi:

|---|---|

## 2. Where I did not take the optional or stronger part of a suggestion, and why

| Finding | Suggested option | Decision | Reason and evidence |
|---|---|---|---|
| V-005 | The admin page generates an X25519 key pair in JavaScript, and the bag returns the zip password sealed to it (TweetNaCl, about 10 KB gzip) | **Not adopted** in phase 1 (recorded in ADR-008 and DATA-EXPORT §6.1) | Someone able to sniff the Wi-Fi can already take the admin session and ask for a fresh export or link (T-2, accepted), so sealing only the password buys little. The library has not been measured on Chrome 58 phones or against the 60 KB chunk budget. Names-included exports now leave by USB by default, which removes the *file* from the Wi-Fi. Revisit together with HTTPS (ADR-004). |
| V-010 | A third backend process bound to upload locations | **Deferred** until CON-1 shows a need | Smaller chunks (2 MiB) cut the time a thread is held to about 10–20 s at 1–2 Mbit/s (a calculation, not a measurement). CON-1 now includes 4 concurrent throttled uploaders with a learner p95 < 300 ms pass criterion. If it fails, the third process is the documented next step. |
| V-014(d) | Prevent browser history from keeping Child protection lesson addresses | **Partly**: `location.replace` inside the portal, plus a documented limit | A web page on plain HTTP cannot erase the browser's history. The quick exit and `location.replace` keep the Back stack clean, but the history list may still show addresses. Lesson addresses contain no learner id and no name. |
