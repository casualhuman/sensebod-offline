# Revision 3: response to ARCHITECTURE-VERIFICATION-3

13 Nov 2026 · System Architecture Agent. This answers `reviews/ARCHITECTURE-VERIFICATION-3.md`, which found the design **approved with conditions on paper**. V-001 to V-024 are closed. V-026 (Medium) was the condition, and V-025 and V-027 to V-029 were Low. The owner asked for all remaining items to be fixed. I accepted every finding and disagree with none. Nothing in `reviews/` or outside `docs/system/` was changed.

**New evidence** (on the development Mac: Node v23.10 with the built-in synchronous `node:sqlite`, and macOS bsdtar/libarchive 3.8.2; **not** a Pi, not 7-Zip):

| File | What it shows |
|---|---|
| `poc/poc_lock_wait.mjs` / `.out` | **V-026.** Another process holds `BEGIN IMMEDIATE` for 1.5 s while the API process makes one write. **A** `busy_timeout=5000`, synchronous wait (the v0.3 text): write after 1,522 ms, **the event loop is frozen for 1,511 ms**. **B** the revision-3 binding default (`busy_timeout=20` plus asynchronous retry with backoff): write after 1,505 ms (10 retries), **max event-loop lag 27 ms**. With a 7 s hold, B gives up with `SQLITE_BUSY_TIMEOUT` after 4,874 ms (→ `503 busy`), lag 33 ms. **C** the allowed alternative (writer in a `worker_threads` thread with `busy_timeout=5000` there): **lag 6 ms**. Lock-hold times of the other writers: job heartbeat commit ≤ 0.17 ms, learner progress commit ≤ 0.25 ms, 500-row retention batch ≤ 2.18 ms, PASSIVE checkpoint ≤ 1.8 ms. A TRUNCATE checkpoint with `busy_timeout=100` and an open reader **gives up after 117 ms** instead of stalling writers. The Mac's `fsync` is not a full flush, so the Pi's microSD will be slower; P-3 and DB-6 decide. |
| `poc/poc_ae2.mjs` / `.out` | **V-027.** A minimal WinZip AES-256 writer and reader using only `node:crypto` and `node:zlib` (no native module, no npm package), cross-checked against libarchive in both directions. (a) A libarchive-written zip opens in our reader; libarchive chose AE-1 for this file, AES-256, and the content matched. A wrong password is refused. (b) Our AE-2 zip with two members (one of 90 KB) is extracted by libarchive with matching content, and libarchive refuses a wrong password. (c) One flipped ciphertext byte is refused (authentication failed). bsdtar takes the password on argv, which is fine for this throwaway test but **not** acceptable in production (R-8). |

**Hardware proofs are still NOT DONE: P-1, P-3, P-4 and P-6** (and P-2, P-5, P-7). The verifier states that final approval depends on P-1, P-3, P-4 and P-6.

| **V-026** (remainder) | The binding default R-3a is now **`busy_timeout=0` plus one in-process single-flight write gate**. DB-6 now includes **200 concurrent writes during a 1.5 s hold**, plus steady arrivals. ADR-002's Decision line no longer says 5000. | SYSTEM-ARCHITECTURE §4.1 R-3L, §14 DB-6; DATABASE §1, §3 (`busy_timeout`), §4 rule 5; ADR-001 (revision-3 note); ADR-002 Decision and note; HANDOFF BE-1 | `poc/poc_lock_wait.out` Part 1b (Mac, `node:sqlite`).
